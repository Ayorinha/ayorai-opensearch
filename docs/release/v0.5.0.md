## 1. Judge 2.0 contract and adjudication

- Implements the versioned Judge 2.0.0 rule contract and deterministic gates G1, G2 and E1–E3.
- Adds atomic and composite rules, canonical output and `verify_output`.
- Adds canonical `r2-a` to `POST /v1/verify`; the existing `r1-a` contract remains byte-identical.
- Adds derived Golden r2 fixtures, canonical explanations, rule trace and generated rule-to-test-to-Golden traceability.
- Uses RFC 8785 canonicalization for `input_sha256` and `output_sha256`.

## 2. API contract and compatibility

- Adds API Contract Guard checks using oasdiff, Schemathesis and an OpenAPI snapshot.
- Completes the response contract and runs Schemathesis with `--checks all`, with documented operation-specific compatibility exclusions.
- Restores legacy `max_agents` coercion on `POST /v1/opensearch` (PR #169).
- References [API changelog](../api/CHANGELOG-API.md) for endpoint-level details.

### Deprecated — removal postponed to v0.6.0

The removal of `ResponseStatus`, the `verification` and `confidence` response fields, and the `r1-a` path with 1.x rules is postponed to v0.6.0. **Nothing is removed in v0.5.0.** Existing clients retain the compatibility surface in this release. The frozen file `rules/judge-2.0.0.json` still carries the label `preserve_1x_wire_contract_until_v0.5.0`. The file is hash-frozen and is intentionally not edited; DEC-008 supersedes that label, and the r1-a path is preserved until v0.6.0.

## 3. Security, provenance and compatibility boundaries

- The deterministic Judge remains the sole authority for the final factual verdict; probabilistic analysis is not the final decision-maker.
- SHA-256 hashes identify the content covered by their digest definitions; they do not prove that a claim is true.
- The documented in-process forgery limitation remains.
- Frozen Goldens, thresholds, manifests and `rules/judge-2.0.0.json` must remain unchanged.
- The Git tag `v0.5.0` and the GitHub Release were created manually by Anderson Leon Ayora on 2026-10-13 after the release PR (#170) was merged; the tag points to main commit e9eccb5.

## 4. Mandatory limitations

- There is no regulatory certification claim and no claim of automatic legal compliance.
- Golden v0 and Golden v0.1 are development/evaluation-development sets, not a production-generalization benchmark.
- The corpus contains 52 synthetic documents tagged `en-US`; results do not establish generalization to genuinely Portuguese source documents.
- Golden v0.1 was rewritten after its author had seen per-case results, so it is not independent confirmatory evidence. Both versions must always be reported side by side.
- Path A is EVAL_ONLY. Path B is only a candidate commercial path subject to independent model-license and provenance verification.
- No claim of universal factual accuracy or production readiness is made.
