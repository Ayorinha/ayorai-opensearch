# AYORAI ATTRACTOR v0.4.0 — Release Notes (prepared)

**Status:** Prepared for review — **NOT RELEASED**  
**Release date:** to be set by the maintainer  
**Git tag:** none created  
**Publication decision:** pending DEC-007

## 1. Contract and verification boundary

- Removed VerificationStatus and EvidenceStore.status(); the evidence store is not an authority for a factual verdict.
- /v1/verify remains the canonical formal-verification endpoint and the deterministic Judge is the only authority for the final factual verdict.
- Separated transport-level abstention into ResponsePolicy. The public verification response distinguishes Verdict from ResponsePolicy.
- Updated the OpenAPI status schema to reference Verdict and ResponsePolicy via anyOf; accepted r1-a wire values remain unchanged.
- Classified five invalid Judge input categories as structured HTTP 422 responses: duplicate evidence IDs, dangling evidence references, duplicate stances, duplicate claim IDs, and stances referencing nonexistent claims. Unexpected ValueError exceptions are not converted indiscriminately into 422 responses.

## 2. Migration notes

### Removed

- VerificationStatus from src/ayorai_attractor/models.py.
- EvidenceStore.status() from src/ayorai_attractor/evidence/core.py.

**Migration:** stop deriving a factual status from the evidence store. Use the formal deterministic /v1/verify contract and its Verdict result.

### Changed

- VerificationResponse.status now represents Verdict or ResponsePolicy; verdict is typed as Verdict | None.
- Search and audit responses do not assert a factual verdict: verification=null, verdict_authority=not_adjudicated, and operational failures are reported separately through operation_status.

### Deprecated

- ResponseStatus remains as a compatibility enum until v0.5.0; new integrations should use Verdict | ResponsePolicy.
- Search/audit fields verification and confidence are deprecated and scheduled for removal in v0.5.0.

**Migration:** update consumers to read the formal /v1/verify result; do not treat verification, confidence, or an evidence-store field as a factual verdict. Consumers should handle structured 422 validation errors for the five classified invalid-input categories.

## 3. Security, provenance and compatibility

- The deterministic Judge remains the sole authority for factual verdicts; language models and orchestrating applications are not authorized to issue the final verdict.
- Golden v0/v0.1, corpus, frozen manifests and F1 thresholds are unchanged by this release preparation.
- The new Q1 coverage work is still under CI/review and must be confirmed on the exact PR head before Phase 1 can be closed.

## 4. Mandatory limitations

- Golden v0 and v0.1 remain development/evaluation-development sets, not a production-generalization benchmark.
- The corpus contains 52 synthetic documents tagged en-US; current measurements do not establish generalization to Portuguese source documents.
- Path A is EVAL_ONLY. Path B is only a candidate commercial path subject to independent model-license and provenance verification.
- v0.4.0 does not claim the future Judge 2.0 rule interpreter, versioned rule_trace, full end-to-end independent reconstruction, regulatory certification, or legal compliance.
- These notes are not authorization to publish, tag, deploy, or make commercial claims.
